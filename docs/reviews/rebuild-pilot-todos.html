H0 先讀：三個與設計書不同的地方

規劃實際操作時，我查了雲端環境的限制，發現設計書有三處需要修正：

設計書寫的實際情況修正做法
§5「隔離靠 repo 權限，不靠提示詞」Claude 的 GitHub 存取是以你的帳號為單位，所有 session 共用。任何 session 都可以用 add_repo 或 GitHub 搜尋碰到你授權過的其他 repo。repo 層級的隔離只能靠「每個 session 掛載哪些 repo」加上提示詞，平台不會強制擋下。(1) 隱藏試題加密後才放進 repo，金鑰只存在 Examiner／Judge 使用的雲端環境（rb-exam），做題方的環境（rb-main）沒有金鑰，即使讀到檔案也只是密文。(2) Integrity monitor 用 list_events 稽核每個 session 的紀錄，檢查是否有越界的 add_repo 或搜尋。(3) 最終報告揭露這個限制。
§6 P0「人類確認一次後離開」，各角色由人類開 session雲端 session 可以用 create_session 建立其他 session，用 send_message 互相傳訊。你只開 Judge 一個 session、輸入一段提示詞；其餘 7 個角色由 Judge 建立並分派。若 Judge 無法建立 session，再改用 H6 的手動備案。
（設計書未涵蓋）5 小時用量上限同一帳號的所有 session 共用用量；用滿時全部停下。Judge 啟動時建立一個每小時觸發的 Routine，喚醒自己巡檢：用量重置後，對停住的 session 傳送「繼續」。這就是你要的「等到重置再自動繼續」。
另一件你要知道的事：目前的環境「rlsentry」網路設定是 unrestricted（不限制），與 CLAUDE.md 的硬規則「只連 localhost、PyPI、GitHub」不符，這也是 Rival 能連到 public.ecr.aws 的原因。試點的新環境一律使用受限網路（H2）。「rlsentry」環境要不要改，等 Rival 結束後再決定：現在改可能讓進行中的 Rival 無法拉取映像。

H1 建立 5 個私有 repo 並授權 Claude 你

1-1 建立 repo（在你的電腦，需要已登入的 GitHub CLI）

每個 repo 都要有初始 commit（--add-readme），雲端 session 才能 clone。

gh repo create pitaya943/rb-spec --private --add-readme --description "rebuild pilot: spec and materials (Product writes)"
gh repo create pitaya943/rb-system --private --add-readme --description "rebuild pilot: implementation (Architect writes)"
gh repo create pitaya943/rb-exam --private --add-readme --description "rebuild pilot: encrypted hidden tests (Examiner writes)"
gh repo create pitaya943/rb-redteam --private --add-readme --description "rebuild pilot: attack reports (Red team writes)"
gh repo create pitaya943/rb-judge --private --add-readme --description "rebuild pilot: orchestration, mailbox, rulings (Judge writes)"

沒有 GitHub CLI 時，在 github.com 右上角「New repository」逐一建立，勾選 Private 與「Add a README file」。

開啟 https://github.com/apps/claude/installations/select_target → 選你的帳號 → Configure → Repository access → 若是「Only select repositories」，把 5 個 rb-* 加進去 → Save。

檢查：在 claude.ai/code 開新 session 時，repo 選單裡看得到這 5 個 repo。

  • 5 個 repo 已建立，各有 README
  • Claude App 可存取這 5 個 repo

2-2 Setup script（兩個環境相同，貼進環境設定的 Setup script 欄位）

以 rlsentry 的 cloud/setup.sh 為基礎，只裝工具、不抓任何 repo 的原始碼；新增映像來源固定為 ghcr.io，以及解密試題用的 age。

#!/usr/bin/env bash
# rb-* rebuild pilot environment: tools only, never fetches repository source.
# Never fails the environment (warnings only).
set -uo pipefail
SUPABASE_VERSION="3.0.0"

pip install --quiet pytest pytest-cov pyyaml httpx ruff mypy mutmut \
  || echo "pip: install failed"

command -v age >/dev/null || (sudo apt-get update -q && sudo apt-get install -y -q age) \
  || echo "age: install failed"

if [ "$(supabase --version 2>/dev/null)" != "${SUPABASE_VERSION}" ]; then
  ARCH="$(dpkg --print-architecture)"
  if curl -fL --retry 5 --retry-delay 5 --retry-all-errors -o /tmp/supabase.tar.gz \
       "https://github.com/supabase/cli/releases/download/v${SUPABASE_VERSION}/supabase_linux_${ARCH}.tar.gz"; then
    sudo tar -xzf /tmp/supabase.tar.gz -C /usr/local/bin supabase || echo "supabase: extract failed"
    rm -f /tmp/supabase.tar.gz
  else
    echo "supabase: download failed"
  fi
fi
supabase --version || echo "supabase: NOT installed"

if ! docker info >/dev/null 2>&1; then
  (sudo -n dockerd >/tmp/dockerd.log 2>&1 &) || true
  for _ in $(seq 1 20); do docker info >/dev/null 2>&1 && break; sleep 1; done
fi
docker info >/dev/null 2>&1 && echo "docker: running" || echo "docker: NOT running"
exit 0

2-3 產生試題金鑰（只放進 rb-exam 環境）

在你的電腦產生一組隨機金鑰：

openssl rand -hex 32

把輸出貼到 rb-exam 環境的環境變數 EXAM_KEY。這不是真正的帳號密碼，用途只是讓做題方的 session 讀不懂試題；它以明文存在環境設定中，只有使用 rb-exam 的 session 拿得到。不要把它放進 rb-main，也不要貼進任何對話或 repo。

H3 驗證環境 你

在 rb-main 開一個測試 session，repo 選 rb-spec，貼入下面的提示詞。它會確認 Docker、Supabase CLI、映像拉取與受限網路都正常，回報後即可封存這個 session。

這是環境驗證，不做任何開發。依序執行並回報每一步的結果（成功／失敗與錯誤訊息），不要修改任何 repo：
1. docker info 是否可用（不可用就執行 sudo dockerd 後等 10 秒再試）。
2. supabase --version 是否為 3.0.0；age --version。
3. 在暫存目錄 supabase init 一個空專案，然後
   SUPABASE_INTERNAL_IMAGE_REGISTRY=ghcr.io supabase start -x studio,imgproxy,realtime,edge-runtime,logflare,vector,supavisor,mailpit,postgres-meta
   回報是否成功、花了多久；若映像拉取失敗，列出被擋下的主機名稱。
4. curl -sS -o /dev/null -w "%{http_code}" https://example.com 應該被網路政策擋下（這是確認受限網路有效，只送這一個請求）。
5. supabase stop。
最後用三行總結：環境是否可用、需要補上哪些主機。

若第 3 步有被擋下的主機，回到 H2 補上後再測一次。第 4 步若沒有被擋，代表網路不是 Limited，請回 H2 檢查。

  • 測試 session 回報四項正常
  • 測試 session 已封存

6-2 輸入的提示詞（整段貼上）

你是重建試點的 Judge，同時負責協調。完整角色說明在 rb-judge/roles/judge.md，流程與規則在 rb-judge/PROTOCOL.md，設計依據是 rlsentry 的 docs/reviews/independent-rebuild-design.html（你不得掛載 rlsentry；那份設計已濃縮在 PROTOCOL.md）。先讀 roles/judge.md 與 PROTOCOL.md，照做。

人類的授權（只限本試點）：
- 你可以用 create_session 建立其他角色的 session、用 send_message 傳訊、用 get_session／list_events 查看狀態、用 create_trigger 建立 Routine。
- 各角色 session 一律直接推送到自己負責的 rb-* repo 的 main 分支（不用 claude/ 分支）；你推送到 rb-judge 的 main。這是人類對所有 rb-* repo 的明確授權。
- 不得 force-push、不得刪除 repo、不得修改 rb-spec 的 CONSTRAINTS.md 與 INTERFACE.md（人類已凍結）。
- 只可連線 localhost、套件來源與 GitHub；只掃描本機 lab。

啟動順序：
1. 建立一個每小時觸發、喚醒你自己的 Routine（名稱 rb-pilot-heartbeat），內容是「巡檢：讀 STATUS.md，檢查各角色 session；用量上限重置後，對停住的 session 傳送繼續；依 PROTOCOL.md 推進下一步」。這是為了在 5 小時用量上限重置後自動繼續。
2. 依 PROTOCOL.md 的角色表建立各角色 session（環境、模型、repo、提示詞都在 roles/*.md 的開頭），把 session id 記在 STATUS.md。
3. 依 PROTOCOL.md 的階段 P1→P5 推進。不要向人類提問；遇到 PROTOCOL.md 列為「交人類」的事項，只記錄在 STATUS.md 的「待人類」區，然後採保守選項繼續。
4. 試點結束（PROTOCOL.md 的停止條件）時：寫 rb-judge/FINAL-REPORT.html，停用 heartbeat Routine，封存各角色 session，最後在對話中用五行告訴人類結果與報告位置。

H7 之後：監看、緊急停止、結束時 你

想做的事怎麼做
看進度讀 rb-judge/STATUS.md（目前階段、各角色狀態、待人類事項、已用輪數）。不需要回覆任何 session。
確認自動繼續有在運作claude.ai 的 Routines 清單中應有 rb-pilot-heartbeat，每小時一次，last run 為 succeeded。
暫停全部在 Routines 停用 rb-pilot-heartbeat，再在 Judge session 輸入「暫停試點：所有角色停在目前的步驟，不要開始新的工作」。
緊急停止（例如發現對外連線）停用 Routine，然後在 claude.ai/code 逐一封存 rb-* 的 session。受限網路已在平台層擋下非白名單主機。
試點結束讀 rb-judge/FINAL-REPORT.html，然後回到本 session 輸入「試點結束」。我會依設計書 §11.2 判斷是否擴大到全系統，並和你進行事後四個問題。
不設美元上限的提醒：你選擇以 5 小時用量上限作為唯一的節流。PROTOCOL.md 仍保留設計書 §9 的停止條件：每個切片紅隊最多 3 輪、同一阻礙連續 5 次失敗即停止，避免無限循環。試點預估在數個 5 小時週期內完成；若超過 7 天仍未結束，Judge 會停止並寫最終報告。
