## 合約

## 完成定義
- `tests/lab/test_scan_writes.py`（`@pytest.mark.safety`）：以 **dev** profile 跑 discover＋build_sessions＋probe，對照每個情境 `profiles` 含 dev 的 write case（insert／update／delete）。斷言：
  - vulnerable write case 得到 confirmed 的 ground-truth rule 與 severity；
  - safe（denied）write cell 的 outcome 為 denied，且沒有 confirmed vulnerability finding；
  - 掃描後 DB log 中 PostgREST 角色的寫入只落在 seeded canary 與其清理（流量檢查）；
  - 掃描結束後所有 canary 都被清掉（以 service_role 確認無 `rlsentry_canary_` 殘留），沒有 CLEANUP_FAILED；
  - 掃描前後 seed.sql 既有列不變（只有 L05 transfer／DELETE 等會改到 seeded 列，不碰既有列）。
  - 測試在每個情境後 `labctl.apply` 還原。
- `tests/lab/test_write_mutations.py`（`safety`）：**必做變異**——以 SQL 製造缺陷後，斷言寫入 oracle／判定以**指定原因**失敗（訊息含 case id 或 `positive control`）。至少涵蓋：把 write_cell 的「2xx 即 allowed」誤判、把 return=minimal 換成 representation 造成的假失敗。
- holdout：在 `/tmp/holdout-MS3/` 寫一組變異方式不同的寫入變異測試，以 `harness/holdout.py add MS3` 加入，sha256 記入 PRODUCTION_LOG 後才可派工。
