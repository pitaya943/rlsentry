## 背景
ADR-029 原設計讓寫入探測共用「每位使用者一筆預先植入的 canary」。但一次成功的跨租戶 DELETE／擁有者轉移會消耗該列，使後續以同一列為目標的探測讀回到錯誤的最終狀態（偽陽性），且清理推理不完整。MS3 的焦點正是「讀回驗證最終狀態」與「清理完整」。

## 合約
`rlsentry/contracts/probe.py` 寫入區塊改為：每個 UPDATE／DELETE 探測在送出前，以所需擁有者的 token 新植入一筆專屬 work row（`seed_work_row`）；INSERT 自建 canary。`WritePlan` 以 `work_owner` 取代 `pk`／`row_owner`；`plan_writes` 不再依賴預先植入列（簽名改為 expected_by_op、user_ids、tokens、text_column）；`send_write`、`after_filter` 改以傳入的 work row；`seed_known_rows` 僅供 dev／ci 讀取已知列使用；`probe()` docstring 更新。ADR-029 補記記錄本修訂。

## 完成定義
- `tests/contracts/test_contract_imports.py` 通過；`ruff check .`、`mypy rlsentry` 無錯誤。
- `tests/probe/test_plan_writes.py`、`test_write_requests.py`、`test_write_verdict.py` 更新為新模型（實作前這些測試會失敗，由 T-126–T-128 執行；本 ticket 僅跑 contract import 測試）。
